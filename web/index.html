Drift Monitor connecting

Live monitoring console

This service sends a fixed panel of canary prompts to a model, compares the new responses with the recorded reference window, and shows what the statistics observed. Every panel answers the same three questions: what is being monitored, whether behaviour changed, and what evidence supports that judgement.

This environment runs a deterministic demo adapter (an offline model stand-in) with a seeded history, so the console is interactive and free of quota costs. It is not continuously monitoring a hosted provider. Related but separate: the README lists all four evaluation scopes (this demo, local Ollama, the recorded Groq vs Gemini hosted experiment, and the simulation evaluation below).

Each run records 10 responses. Statistical tests begin once 60 responses are stored.

Detection delay and false-alarm trade-off

The same simulated shift, four alert policies. Merging evidence across cycles (the k-of-n and persistence rules) trades a little speed for a large reduction in noise. The shipped policy is persist2, the two-cycle persistence rule.

Power curves at the production window

Detection power (probability of flagging) for each test against increasing simulated shift magnitude, at the production current window of 10 responses. Even a real but small shift can be invisible at this sample size, which is exactly the limitation stated elsewhere.

Matched prompt diagnostic

A methodological companion to the semantic detector on the Console tab. The standard MMD permutation test exchanges individual responses; this diagnostic instead exchanges complete response sets belonging to the same matched prompt, which respects the fact that repeated probes to one prompt are not independent observations. Same data as the pooled test, so the two numbers are expected to agree in these runs; the diagnostic is the one that stays valid when prompt effects are large. Ten matched prompts still provide limited evidence, and this diagnostic is not wired into production alerts.
